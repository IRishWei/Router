# 路由方案讨论记录

本文件记录已确认的设计选择；尚未确认的建议不作为实现要求。

## 已确认

### Q1：默认执行方式

采用 C：先做轻量判断，选择起始模型，执行中再根据证据调整。

调整触发条件与恢复规则见 Q5、Q13；具体判断信号和开销在规格中明确，并通过接入验证检查。

### Q2：效果验证的对照方案

接受三类对照：低成本模型全程执行、强模型全程执行、最接近的社区插件。
当前社区候选为 oh-my-dsh；在正式对照前验证其宿主兼容性。

### Q3：第一批效果验证的任务范围

首批覆盖编程、写作、研究和图像理解，分别制定验收方法。

### Q4：额外模型评审

有条件允许：优先使用已有测试、规则和工具结果；证据不足或风险较高时，
可在预算内追加模型评审。区分检查结果、模型评审意见与无法确认的部分。
证据分级与复核次数见 Q8。

## 外部事实与待验证事项

- oh-my-dsh 源码包含同一 session 的模型切换、直接调用其他模型的咨询与评审工具，
  以及配置页面。因此咨询、切换和配置页面本身不构成已证明的独特性。
- 未发现该项目具有验证结果驱动的路由收益评估与策略更新闭环；此结论受检查范围限制。
- 它声明的 DSH peer 范围为 ^0.1.0-rc.6；在当前 0.2.0-rc.2 桌面版中的兼容性未经运行验证。
- 一手来源：https://github.com/llmpolska/oh-my-dsh/blob/main/lib/agent.js
  和 https://github.com/llmpolska/oh-my-dsh/blob/main/package.json 。

## 已确认（续）

### Q5：咨询与接管的触发条件

- 首次出现可修复问题，允许当前模型自行修正一次。
- 同类问题再次出现，或明确缺乏解决问题所需的能力，咨询更合适的模型。
- 采纳咨询建议后仍无法通过验收，或咨询指出必须重做整体方案，再考虑接管。
- 网络故障和限流由连接恢复机制处理，不作为任务困难的证据。
- 默认次数可配置；不因一次普通报错直接升级。

### Q6：自动化效果验证

用户要求效果验证完全自动化，不安排人工评分。
开放式任务的自动评分不能直接等同于真实质量；证据分级、冲突处理及学习限制见 Q8、Q15。

### Q7：效率与质量门槛

- 编程、写作、研究、图像理解分别检查质量，不用某类提升掩盖另一类退化。
- 总资源消耗或完成时间至少一项改善 15%。
- 另一项退化不超过 10%。
- 允许个别任务变贵或变慢，但完整报告分布，不只挑选成功样例。
- 报告实际费用、token 和耗时；费用为主要资源指标（见 Q9），适用对照待确定。

### Q8：自动验收的不确定结果

- 明确要求由测试、规则或已知答案检查。
- 开放式质量使用匿名模型评审；必要时在预算内追加一次复核。
- 证据不足或评审冲突时标记为“无法确认”，不强行判定成功。
- 无法确认的结果不用于奖励路由策略；实验报告展示其比例。
- 只对检查覆盖的质量作出结论，不将自动评审意见等同于整体质量保证。

### Q9：主要资源指标

用户选择实际费用作为主要资源指标，不以总 token 作为默认主要指标。
仍记录 token 和耗时。费用、订阅参考价值与未知数据的口径见 Q11、Q14。

### Q10：首版上下文交接

- 咨询模型只接收当前问题及相关证据。
- 接管模型接收完整、可跨模型表达的对话与工具记录。
- 切换前检查上下文容量及格式兼容性。
- 无法可靠交接时取消此次切换并显示原因，不静默截断后继续。
- 上下文压缩作为后续单独验证的优化，首版不将其作为已交付能力。

### Q11：费用计算方向

- API 按调用用量与 API 价格计算费用。
- 订阅模型结合额度占比、消耗 token 与 API 价格估算资源价值。
- 订阅数据缺失与参考价值的显示口径见 Q14。

### Q12：配置与管理界面

- 三页：连接与模型、路由与预算、任务记录；首次使用提供简短引导。
- 连接与模型：连接账号或填写密钥、发现模型、显示能力/价格/连接状态、勾选模型。
- 路由与预算：默认均衡模式；支持目标、预算、自动路由开关、手动固定及折叠高级参数。
- 任务记录：结果、费用、耗时与路由过程；日常显示当前模型、选择原因和预算进度，细节可展开。
- 不要求用户为模型手动指定固定角色；必要官方登录使用浏览器授权。

### Q13：异常恢复

- 咨询失败时保留当前模型和任务状态。
- 连接故障有限重试；可改用已启用且符合能力及预算要求的替代模型。
- 手动固定模型时不自行换模型。
- 插件能捕获的内部异常暂停本任务自动路由并显示原因，尽量保留原生执行路径。
- 需重新授权、预计超预算或无法可靠交接时暂停。
- 结果不明的操作不直接重做，避免重复副作用。

## 订阅数据可用性核查

- 官方 SIWC 文档提供订阅用量管理入口和超限错误；本次审阅未找到面向第三方的额度百分比读取契约。
- Responses 定义 token 用量明细，但 SIWC 各账号/模型的实际返回完整度仍需测试；缺失记未知。
- 账号模型目录提供模型 ID；未找到覆盖所有订阅模型的 API 定价映射或 API 参考价值到订阅额度的换算公式。
- 多个应用可共用订阅额度，插件自己的 token 累计不代表账号整体使用占比。
- 来源：https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions#tracking-usage
  和 https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference 。

## 已确认（续二）

### Q14：订阅额度未知时的估算与展示

- 有实际 token 用量与可信价格映射时，计算 API 价格参考值。
- 有可信额度占比时，用于判断额度稀缺程度并影响路由。
- 额度占比缺失时显示未知，不推算虚假的账号整体百分比。
- 实际支出、订阅参考价值、额度状态分别展示；参考价值不冒充账单。
- 缺失数据不用于证明实际费用节省 15%。

### Q15：策略学习的真实试用

- 默认记录结果并进行影子计算，不自动重复付费执行任务。
- 用户在界面一次性开启策略试用后，允许少量符合能力及预算要求的任务使用候选策略。
- 初始试用比例不超过 5%；证据充分、达到效果门槛后才扩大采用范围。
- 明确退化时回退；无法确认的验收结果不作为成功奖励。
- 用户可查看变化原因、关闭学习或恢复原策略，无需逐任务干预。

### Q16：开发与停止条件

- 复用经过兼容验证的接入组件，重点自研验收证据驱动的决策、效果评估和统一交互。
- 路由效果与社区相当而界面明显更好时，可转为集成与交互改进项目。
- 性能与体验均无实质优势时，停止自研路由层，改为使用或扩展现有方案。
- 不以代码全部自写为目标，不预先宣称路由效果优于社区。

## 前轮已确认的运行边界

- 免费、开源、本地运行；首发适配 Windows DSH Desktop 0.2.0-rc.2。
- 在 Codex 中开发，在 DSH 中实验；配置及授权独立，不读写 Codex 配置或认证文件。
- 首版单 agent，支持咨询及稳定边界接管；多子 agent 与 MoA 不纳入首版。
- 首批来源为 DeepSeek API、OpenAI API、独立官方 ChatGPT OAuth、OpenAI 兼容端点；发现已有 DSH 连接。
- 默认均衡模式，另可选择费用、token、速度或质量优先。
- 一个独立用户请求为一个任务；执行中的补充或纠正归入当前任务。
- 预算统计包含判断、咨询、执行、评审、重试及重做。新调用前估算，预计超限时暂停确认。
- 单次请求的实际消耗可能超出估算，不承诺绝对账单硬上限；用量、价格与额度缺失记未知。
- 运行中配置变更在下一稳定边界生效，界面区分待生效与已生效。
- 可选小预算校准；默认无需校准即可使用保守起始策略。
- 学习与记录保存在本地；仅影子计算不视为已证明候选策略的质量。

## 总体确认与工程验证

Q1—Q16 均已逐项确认，用户已确认完整方案总结并授权进入 to-spec。
首版规格已发布至 https://github.com/IRishWei/Router/issues/1 ，标签为 ready-for-agent。
运行兼容性与效果属于待实测事项，不能视为本轮讨论已证明的结论。

用户已确认以完整任务的可观察行为作为主要测试入口：检查最终模型选择、咨询/接管、
验收状态、费用口径、预算处理和路由记录。使用可控模型响应验证故障恢复，
再在真实桌面宿主检查安装、配置、模型选择优先级及跨模型交接。

效果评估使用冻结的四类任务与相同输入、模型池、配置条件；记录失败、无法确认、
完整消耗和耗时分布。分别报告各对照差异，不把固定模型对照收益等同于优于社区。

待实测门槛包括：桌面模型选择与原生控制器协同、官方授权与模型权限、
订阅用量和价格映射可用性、跨提供商上下文/工具协议兼容性、自动评审可靠程度，
以及是否达到约定的效率和质量门槛。
